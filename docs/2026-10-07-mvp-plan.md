# 桌面常驻智能体：产品边界与实施计划

日期：2026-10-07。状态：M0 开发计划。依据：[前期调研](./2026-10-07-desktop-resident-agent-research.md)。项目代号：桌面常驻智能体；第一版仓库包名：`desktop-resident-agent`。

## 1. 要解决的问题与交付目标

用户想要一个常驻 Windows 桌面的二次元角色，既能自然交流，也能在授权范围内真正完成电脑任务。单独的桌宠动画、聊天窗口或一次性的电脑操作演示，都不足以证明这三部分构成了同一个可用产品。

产品目标是让同一角色拥有可见的状态、任务上下文与可核验的行动：接收请求，提出下一步，获得必要批准，执行，重新读取结果，再向用户报告。这里的“自主”指可观察的任务规划和闭环执行；主观意识不作为可验证的交付承诺。

首个交付物是一个能安装依赖、构建并在 Windows 上运行的本地应用。它含可点击、可拖动的小型桌面角色，以及贴在角色上方、可收起的交互气泡；有 `deepseek-flash` 在线模型接口；未经显式启用时清楚显示 Demo 模式；能在限定测试目录中提议并在逐次批准后创建真实文件。语音、全桌面 GUI 操作、气泡常驻和长期记忆按后续里程碑推进。

## 2. 用户故事

1. 作为用户，我希望角色常驻桌面、可点击与拖动，并能打开任务面板，以便随时呼叫它。
2. 作为用户，我希望看到角色当前是待机、思考、等待批准、执行、完成还是出错，以便知道它正在做什么。
3. 作为用户，我希望输入自然语言任务并看到回复、步骤和结果，以便判断任务是否真正完成。
4. 作为尚未提供 API Key 的用户，我希望明显看到 Demo 标记及其能力边界，以免把示例回复误认为真实模型推理。
5. 作为已配置 API Key 的用户，我希望应用安全地调用 DeepSeek V4.1 Flash，并在网络或配置错误时得到可操作的提示。
6. 作为授权任务的用户，我希望每次写入前看到规范化后的目标路径与完整写入内容，并能批准或拒绝，以便控制实际改动。
7. 作为用户，我希望拒绝、暂停或关闭任务后不再发生待执行的写入，以便随时收回授权。
8. 作为用户，我希望在任务结束后看到执行记录及文件读取验证结果，以便区分“模型说完成了”和“文件确实存在”。
9. 作为语音用户，我希望用中文说话、看到识别结果、听到回答并能打断它，以便像与角色对话一样操作。
10. 作为电脑任务用户，我希望以后逐步授权窗口、浏览器和工具操作，并看到每步证据，以便放心交付跨应用任务。

## 3. 阶段与验收

| 阶段 | 要做的事 | 完成条件 |
|---|---|---|
| **M0：可信的最小闭环** | Electron + React + TypeScript 本地应用；小型桌面角色和同窗口的交互气泡；本地任务状态；`deepseek-flash` 接口；明确 Demo；仅限 `D:\DesktopPetProject\sandbox\notes` 的真实新文件创建 | 已验收，见 [M0 预览验收记录](./2026-10-07-m0-acceptance.md)。 |
| **M1：可打断的语音实体** | 麦克风权限、中文 ASR（Web Speech API + SiliconFlow 在线回退）、partial/final 字幕、分句 TTS、播放打断与角色口型/状态关联 | 进行中；详见 [M1 实施计划](./2026-10-08-m1-voice-plan.md)。 |
| **M2：受控 Windows 操作** | 评测本机 Windows-MCP 与 Cua Driver；窗口/UI 树/截图观察；逐步动作、再观察与证据；任务级工具权限和紧急停止 | 在指定测试应用与文件夹中完成事先定义的 3 个跨应用场景；每步有动作和结果记录；取消后不再继续输入或启动下一步 |

M0 是当前“开干”的实施边界。M1 和 M2 的具体模型、角色素材与工具实现，在各自开始前由实测结果决定；阶段完成以可复现的验收为准，不以功能列表或演示视频代替。

### M0 详细验收清单

1. **可运行**：新检出的项目按 README 安装和构建成功；Windows 本地启动出现小角色，点击后在角色上方展开同窗口气泡；退出后进程结束。构建失败或只能在开发服务器中看见页面均未完成。
2. **实体交互**：角色可拖动；气泡由角色左键切换开合，右键菜单只有退出。当前不提供气泡置顶开关。点击与拖动不会穿透到下面的窗口。至少在本机当前缩放比例下由用户人工验证；125% 缩放及多显示器列入单独回归记录。界面使用用户参考图派生的本地预览素材，后续可更换视觉资产。
3. **状态可信**：待机、请求中、等待批准、执行中、完成和错误的状态在气泡中可分辨。一次任务的步骤与结果可查看；网络失败不会显示“完成”。
4. **默认可演示**：未经显式启用在线模式时，界面持续显示 `Demo`，提供离线示例对话；示例内容明确标为模拟，不伪称调用 DeepSeek，也不自动执行文件操作。
5. **真实模型接口**：同时显式设置启用标志和 Key 后由受信任的本地进程调用 `deepseek-flash`，Key 不进入渲染进程、前端包、日志或任务记录。至少验证一次文字回复；若开发时尚无本任务提供的 Key，自动化测试只证明接口契约与错误处理，实连状态写成“待凭据验证”。
6. **写入范围**：唯一允许的 M0 写入动作是向 `D:\DesktopPetProject\sandbox\notes` 创建**全新的**文本文件。执行前把候选路径解析到实际目标并确认仍在该目录；拒绝路径穿越、目录外路径、已存在目标和会跳转出目录的链接。不得覆盖、删除、重命名或执行 shell 命令。
7. **逐次批准**：每次真实写入都展示规范化目标路径与完整内容，等待用户明确批准。批准仅对当前待执行动作有效；拒绝、关闭面板或结束任务不得写入。批准后若文件状态变化，重新校验并安全失败。
8. **结果验证**：执行后读取新文件并核对内容，再报告路径、结果和失败原因。至少人工或自动化演示“批准成功”“拒绝无文件”“越界/同名被拒”三条路径。一个成功的文件系统调用本身不算任务完成。
9. **可审计**：本地记录任务请求、提议动作、批准/拒绝、执行结果与验证结论；记录不含 Key。用户能在面板查看本次任务记录。

## 4. 实现决策

- **本地应用结构**：Electron 主进程承载模型调用、文件工具、审批状态和持久化；React + TypeScript 渲染角色与任务面板。渲染进程只通过明确的 IPC 契约请求能力，不直接接触 Node 文件系统或 API Key。
- **任务闭环**：模型输出只是提议。编排器先做参数校验和范围检查，再生成待批准动作；批准后才执行，随后读回验证。所有 UI 状态由执行事实驱动。
- **权限最小化**：M0 只开放 `create_note` 一类文件能力；没有通用命令、任意文件读取或桌面控制工具。后续新增能力分别定义授权范围、证据和撤销方式。
- **Demo 与在线模式分离**：Demo 由固定的本地脚本提供示例内容，始终有明显标记；在线模式必须真实调用指定模型。在线请求错误原样归类为配置、网络或服务错误，避免静默回落并混淆来源。
- **配置和秘密**：Key 通过本地环境或受保护配置传给主进程，任何日志与 UI 只显示已配置状态，不回显值。持久记忆与角色人格属于后续设计，不让首版借此扩大数据收集。
- **视觉资产**：先使用原创占位图形或可明确授权的素材。DeepSeek 鲸鱼娘及第三方模型/声线只作参考，发行许可另行确认。

## 5. 测试范围和交付证据

自动化测试放在高层业务边界：任务提交、提议验证、审批、文件执行与读回结果。重点测批准后新建文件、拒绝无副作用、并发/重复批准不重复写、同名文件保护、路径穿越及链接逃逸、无 Key 的 Demo 标记、API 错误状态。测试不以内部函数被调用次数代替用户可见结果。

构建测试验证 Electron 与前端可以产出可启动应用。GUI 的点击、拖动、穿透、缩放、焦点与关闭行为需在 Windows 桌面人工验收；无桌面会话时记录为待验证。M1 增加延迟、识别文本、打断和回声测试；M2 使用固定的跨应用任务、成功证据与失败恢复脚本，不以通用基准成绩替代本机验收。

交付时保留：启动说明、配置说明、已运行的测试和结果、人工 GUI 验收记录、已知限制。未获得 DeepSeek Key、麦克风或 GUI 操作授权时，如实标明相应项目未实测。

## 6. 关键风险与后续决策

| 风险或决策 | 当前处理 |
|---|---|
| DeepSeek 返回内容可能误导或提出越界操作 | 工具能力由本地白名单和路径校验限定；模型不能直接执行 |
| Electron 透明窗口在 DPI、拖拽和输入区域有兼容问题 | M0 用真实 Windows 窗口人工验收；既往桌宠故障只作回归提醒 |
| Windows-MCP 能力过宽，且与其他客户端的配置不等于本产品可用 | M2 单独做连接、权限和稳定性评测，再决定是否接入 |
| 流式语音、TTS 声线和二次元素材各有质量与许可问题 | M1 先验证固定授权音色与可打断交互；M0 采用用户提供参考图制作的本地预览形象，公开发行前核实原图权利或换原创素材 |
| 角色主动行动可能造成打扰或误操作 | 主动提议与自动执行分开；用户可关闭主动提醒和停止任务 |

## 7. 当前不纳入 M0

任意磁盘读写、覆盖或删除个人文件、shell/注册表/进程控制、无人看守的全桌面操作、游戏自动控制、长期记忆、开机自启、远程访问、公开发行版、可验证的“意识”。这些属于后续明确边界与单独验收的能力，不是 M0 的隐含承诺。

## 8. 下一阶段方向

实体交互已由用户验收。当前预览已通过本机 Claude Code 与 DeepSeek 的非 GUI 连通测试，并用官方 Agent SDK 接入流式文字、停止和六类内建工具；按用户当前要求，这六类工具无需逐次批准即可执行。工具的可见操作仍待用户验收。后续参考本机 Claudian 2.2.4，加入 turn/session ID 续接会话、工具输出卡与持久上下文。Windows-MCP 和其他本机 MCP 尚未接入本应用。角色人格、记忆和语音共用同一任务状态。UI 验收继续由用户逐项反馈；皮肤与选项入口留待实际功能落地时加入右键菜单。
