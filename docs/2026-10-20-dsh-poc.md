# DSH PoC 记录（Phase 2）

日期：2026-10-20

## 版本

- `@deepseek-ai/dsh@0.2.1-rc.2`
- `@deepseek-ai/dsh-sdk-minimal@0.2.1-rc.2`
- `@deepseek-ai/dsh-sdk-protocol@0.0.1-rc.1`（显式依赖）
- 模型：`deepseek-official` / `deepseek-v4-flash`
- 运行时：Windows 11，Node 24.16.0

## 结论

DSH 可以跑通真实会话：初始化、流式事件、工具调用、工具结果、后续文本、turn 结束。**但 npm 的依赖树不行，pnpm hoisted 依赖树才行。**

### npm 树的问题

npm 安装后，`working_directory` 和 `pwsh` 都被记录为 `tool/call`，随即收到：

```
TOOL_OUTCOME_UNKNOWN
The tool call was interrupted after it was recorded, but no result was durably recorded.
```

根因是工具调度服务解析到了不一致的包副本/服务键：`ctx.tools[TOOL_RUNTIME_SCHEDULER]` 为空，`prepare()` 抛出后 agent-loop 把该步骤关闭并补了一条恢复结果。补 `dsh-sdk-protocol` 和 `npm dedupe` 都不能修复。

### pnpm hoisted 的修复

在 `reference/dsh-poc-pnpm`：

```ini
node-linker=hoisted
enable-pre-post-scripts=true
```

依赖：

```json
{
  "@deepseek-ai/dsh": "0.2.1-rc.2",
  "@deepseek-ai/dsh-sdk-protocol": "0.0.1-rc.1"
}
```

（`dsh-sdk-client` 在 pnpm 严格布局下解析不到自己的协议包，PoC 改用直接 JSON-RPC，不再依赖客户端库。）

结果：`tool/call` 后收到真实 `tool/result`（当前目录），随后 assistant 输出 `OK`。这是 Phase 2 的通过标准。

## 事件序列（实测）

一次带工具的回合：

```
agent/inbox/spliced
turn/start
step/start
system/message
user/message (prompt + runtime context)
request/header
request/context
session/title
session-log-deepseek/delivery-accepted
assistant/message   ← content: reasoning / text / tool-call; usage 在同一事件
tool/call           ← callId, name, arguments(JSON string)
tool/result         ← message.content, isError, callId
step/end / step/start (tool 后下一模型步骤)
assistant/message   ← 最终文本
turn/end
session.status idle
```

## 协议

- 传输：stdio，按 `\n` 分帧 JSON-RPC 2.0；stdout 只放协议。
- 方法：`initialize`、`session/prompt`、`session/resume`、`session/wait`、`session/working-directory/{get,set}`、`shutdown`。
- 通知：`session.event`、`session.status`、`subagent.started`、`subagent.finished`。
- `initialize.params`: `{ cwd, provider, model, maxTokens? }`。
- `session/prompt.params`: `{ sessionId, contentBlocks: [{ type: 'text', text }] }`。
- 限制：协议没有逐提示词取消，也没有逐提示词结果；取消只能关闭运行时。迁移适配器必须把“停止”映射为重启运行时或应用层中断。

## 复现

```powershell
cd D:\DesktopPetProject\reference\dsh-poc-pnpm
$env:DSH_HOME = "$PWD\.dsh-home-manual"
$env:DEEPSEEK_API_KEY = (Get-Content "$HOME\.claude\settings.json" -Raw | ConvertFrom-Json).env.ANTHROPIC_AUTH_TOKEN
node manual.mjs
```

`manual.mjs` 发送 initialize，再发一条带 `working_directory` 的提示词，并打印事件。

## 对迁移的影响

- 生产不能直接用 `npm install` 后的 DSH；要么随包提供 pnpm hoisted 的独立 runtime，要么在构建时做依赖扁平化并验证 `TOOL_RUNTIME_SCHEDULER` 解析一致。
- 适配器应使用直接 JSON-RPC，不依赖 `@deepseek-ai/dsh-sdk-client`（pnpm 布局下其协议包解析有问题）。
- DSH 工具调用的取消/审批需要应用层补齐；sdk-minimal 的默认 danger-full-access 不能直接暴露。
- 阶段 3 先实现单会话的 DshAgentClient，再替换主链路。
