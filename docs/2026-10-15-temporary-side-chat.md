# 同窗口临时侧聊：v0.0.61 实现与验收

> 状态：以下按 2026-10-16 本机 v0.0.61 源码记录。主进程、IPC 与气泡界面已接通；可见界面的点击手感仍待用户验收。临时侧聊不是会话库里的新会话，也不是从旧回复创建的持久分支。

## 参照与产品边界

Real Claudian 的 `/side`、`/btw` 从主会话开启独立的临时子运行时。展开时，共享输入框向侧聊发送；折叠时，输入框回到主线。Claudian 每个 tab 可保留一条侧聊，切 tab 不销毁。参照源码：`reference/claudian/src/core/commands/builtInCommands.ts`、`features/chat/side-chat/SideChatController.ts`、`SideChatSession.ts`、`SideChatPanel.ts` 与 `features/chat/input/InputController.ts`。

小鲸在现有桌面气泡内切换主线与侧聊，不另开窗口。初版主进程**只保留一条**绑定当前显示主会话的侧聊；切换主会话会停止并丢弃它，回到原主会话也不会恢复。应用退出时同样丢弃。这是与 Claudian 每 tab 保留侧聊的主要差别。

## 当前使用方式

- 在主线输入 `/side 问题` 或 `/btw 问题`，会展开侧聊并发送问题；模型支持附件时，无文字但附文件也可开启。只有命令、没有问题和附件时不启动侧聊，原草稿仍留在输入框；`/sidebar` 不会被识别为侧聊命令。
- 侧聊只会绑定当前仍在会话库中活动的主会话。关闭、归档或删除最后一个主会话后，旧 ID 不能开启隐藏侧聊；已保存的 Claude Code 会话在引擎不可用时会按实际运行模式显示演示模式。
- 从主线再次输入带问题或附件的 `/side`、`/btw` 会展开当前侧聊并续问，不覆盖已有消息。侧聊展开时不能嵌套开启侧聊；输入 `/new`、`/goal`、`/compact` 等应用命令会被拒绝。模型菜单的「压缩上下文」按钮路由到侧聊，能否完成仍取决于模型引擎状态。
- 气泡只有一份输入框。侧聊展开时显示其消息、工具、队列与待审批事项；收起后显示主线，侧聊缩成可再次展开的入口。主线与侧聊各有草稿和附件；主线草稿沿用会话草稿保存机制，侧聊草稿只在当前界面内保留。
- 侧聊可以与主线任务同时运行。发送、介入、停止、队列编辑、审批、上下文用量和费用按各自运行时处理。停止侧聊会暂停其队列并保留待发消息；再次发送新消息可继续处理。丢弃则清空侧聊队列和草稿，并停止其运行时。

## 背景与数据生命周期

1. 开启时从当前主会话的**可见且已结算** user/assistant 对话取得有界背景：最多最近 20 行、总计 16,000 字符。工具输出、隐藏会话上下文、敏感轮和主线 `sdkSessionId` 不复制。主线正在执行时仍可开启；未结算的最新回复不会进入背景。没有合格历史时，侧聊从空背景开始。复制的背景只供模型参考，不显示为侧聊消息。
2. 侧聊使用独立 `AgentRuntime`，消息、队列、状态与费用不进入 `ConversationStore` 或主线时间线，也不成为会话标签或会话搜索结果。侧聊不会触发主线的成功回合记忆提取；模型请求仍可读取已有长期记忆。侧聊 Claude SDK 设置 `persistSession: false`，不会把侧聊 transcript 写入 SDK 会话目录。
3. Claude Code 侧聊在热查询仍存在时沿用它；查询失效后以 `boundedConversation` 中的内存历史冷重放。DeepSeek 走自身的有界历史。背景可能缺少旧工具过程或原生压缩上下文，因此界面只称「临时侧聊」，不保证完整继承主线。侧聊一旦被丢弃，迟到的运行时事件不会恢复它。
4. 模型配置或身份等运行配置变更也会丢弃当前侧聊。此行为和切换主会话一样，应在有侧聊任务时留意；侧聊本身不保留可跨应用重启的草稿或运行状态。
5. 粘贴文件沿用应用的附件暂存流程，会在 `data/attachments` 生成副本。当前暂存目录同时服务主线与侧聊，尚无侧聊文件的独立归属与清理机制；丢弃侧聊只清聊天记录和队列，不会删除已暂存的附件副本。后续清理应先给暂存文件记录归属，并避免删除仍被主线引用的文件。

## 与原生分支的差别

Claudian 的持久 fork 可把来源 session ID 和 assistant checkpoint 交给 Claude SDK，以 `resume`、`resumeSessionAt`、`forkSession: true` 创建新的原生 session。小鲸尚未把稳定 checkpoint 映射到每条完成回复；主线的 `sdkSessionId` 是整段会话的恢复 ID，直接复用会串线。v0.0.54 曾提供最新回复的历史冷复制入口，v0.0.59 已移除；本版临时侧聊没有恢复该入口，也不会回滚电脑文件。历史方案见[已撤销的冷复制设计](./2026-10-14-conversation-fork-design.md)。

## 验收重点

1. `/side 问题`、`/btw 问题` 可从主线开启，支持附件的模型可只附文件；没有问题和附件时保留草稿。主线运行中开启时仅带入此前已结算的可见对话。
2. 侧聊展开、收起、再次展开或从主线续问时，消息、草稿、附件和发送归属互不混入；小窗与放大态均使用同一输入框。
3. 两边同时运行时，回复、工具详情、队列、停止、审批、上下文用量与费用各归其主；侧聊中输入 `/compact` 会被拒绝，模型菜单的压缩按钮仅操作侧聊。
4. 切换主会话、丢弃侧聊或重启应用后，侧聊及迟到事件不再出现；原主线记录仍完整。此点是小鲸单活限制，与 Claudian 切 tab 保留侧聊不同。
5. 侧聊首轮不使用主线 `sdkSessionId`，其聊天记录不写入 `data/conversations/records` 或 Claude SDK transcript。现有气泡自动化见 `test/panel-side-chat-dom.test.tsx`；可见点击另行验收。
