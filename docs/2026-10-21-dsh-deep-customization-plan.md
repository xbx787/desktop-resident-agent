# 从 0.0.92 开始：DSH 深度定制计划（2026-10-21）

0.0.92 把这些年积压的界面和宿主侧问题收了一轮。从这一版起，目标不再是“让 DSH 能跑”，
而是“让 DSH 完全长成这个项目需要的样子”。

0.0.92 已打包：`release/whale-companion-v0.0.92`，包含原生插队（`session/steer`）、图片/文件输入、
审批四档、联网与压缩开关、子代理托盘、工具名汉化、切换对话回底。

## 一、现状盘点

宿主侧已经做完的：

- 原生插队（`session/steer`，ACP 补丁 + 打断式回退）
- 图片发送：4 MB 内联、更大走文件引用（附件 50 MB、预览 24 MB）
- 文件附件：文本内联、路径引用
- 审批四档、手动审批逐条询问、计划模式只读
- 联网搜索真正禁用、自动压缩阈值、输出风格/追加指令注入
- 子代理托盘（任务级）、工具名全汉化、工具行三档、切换对话回底

## 二、阶段 A：ACP 桥扩展（补丁维护）

都靠 `scripts/patch-dsh-runtime.cjs` 的同一套机制，幂等、打包前自动跑。

1. **子代理父子关系**：`tool/call` 事件加父调用 id，宿主把子代理内部工具归到托盘下。
   需要动 `dsh-agent-loop` 的事件载荷和 `dsh-acp` 的映射。验收：子代理里跑三条命令，
   主时间线不出现散落的工具行。
2. **询问作答**：新增 ACP 请求 `session/ask`（问题 + 选项），宿主弹出已有提问面板，
   回答回传。验收：模型调用提问工具时面板出现，回答能回到模型。
3. **手动压缩**：新增 `session/compact`，宿主按钮（这次删掉的）可以加回来。
   验收：手动触发后上下文占用下降。
4. **图片能力上报**：把 `promptCapabilities.image` 暴露给宿主，设置里显示“当前模型是否支持看图”。

## 三、阶段 B：DSH 内核定制

1. **工具集裁剪**：只保留本项目需要的工具，去掉 goal 等重复能力，减少模型乱调。
2. **提示词分层**：人设、宿主规则、输出风格分开维护，不再拼在一个大字符串里。
3. **计划模式原生化**：用 DSH 的 plan-mode 插件做完整闭环（提交计划 → 批准 → 恢复权限），
   不再靠“只读沙箱 + 拒绝”。
4. **多模态路由**：按模型能力决定内联图片还是走读图工具，并在 UI 上说明当前走哪条。
5. **会话内命令**：把 DSH 的 `/compact`、`/goal` 等命令接到宿主命令面板。

## 四、阶段 C：分发与可组装

1. **补丁清单化**：每个 vendor 补丁一个文件、一个测试，升级 DSH 时逐条重放。
2. **插件/Skill/MCP 市场接入**：库页面接开源市场，安装即用。
3. **可复现构建**：固定 DSH 版本、补丁哈希、打包产物校验和。
4. **回退**：任何补丁失败时自动退回未打补丁的运行时，并给出中文原因。

## 五、约定

- 不直接改 DSH 的 npm 包内容而不留记录；所有 vendor 改动必须能在补丁脚本里重放。
- 每次升级 DSH 版本，先跑补丁脚本和全量测试，再打包。
- 用户可见文案一律中文，工具名不超过四个字，说明文字优先中文。
- 长任务过程中分段汇报进展，不闷头做完才说。
