# CrossPet 对小鲸 Live2D 的可借鉴部分

研究基线为 CrossPet 提交 [`6e98970`](https://github.com/lokicorvus/crosspet/tree/6e98970f6ff9b44e8ac85215241cabcd78f67d92)。结论是保留小鲸的 Live2D Cubism 路线，只借鉴行为与状态架构。

## 本轮已经采用

1. **工具语义适配层**：DSH 和 MCP 的具体工具名先归一成读取、写入、终端、搜索、绘图、委派和其他，再交给人物表现层。
2. **适配器类别优先**：DSH 提供可识别 `kind` 时直接使用；名称匹配只做兼容回退，避免 UI 与某一套工具命名绑定。
3. **能力不足时回退**：正式模型可逐项绑定动作；技术样例缺少动作时继续使用通用 `Working`，并避免共享同一 motion 的语义切换造成重启闪烁。

## 下一阶段值得采用

1. **带来源和顺序的纯状态 reducer**：事件携带来源、会话、回合、序号与时间，拒绝已结束回合的迟到事件，并给短工具动作最短可见时长。
2. **多会话聚合**：标签圆点保留各会话状态，人物本体按照等待用户、拥挤、忙碌、完成或失败的优先级表现当前最需要关注的状态。
3. **Live2D 角色包契约**：为每个原创角色声明 model3、语义动作映射、缺失动作回退、待机权重、点击区域、表情、语音和素材许可。
4. **外围状态特效**：由 Live2D 负责身体、头发、表情和口型，SVG 或 Canvas 只表现文件、终端、搜索、成功等轻量道具。
5. **功耗控制**：人物不可见时暂停 ticker，长时间闲置时降帧，有任务或交互时恢复。

## 不采用

- 不用静态整图的上下浮动、摇晃和抖动替代 Cubism motion、expression 与 physics。
- 不复制 CrossPet 的角色立绘、提示词或人设。
- 不照搬全局网页状态机和文件轮询；小鲸继续使用类型化事件与模块化 reducer。
- 不只靠工具名子串判断状态；名称匹配始终是适配器类别缺失时的回退。
