# 自我进化审批模式（2026-10-20）

## 目标

在现有审批层级之上增加一档「自我进化」：在完全访问的基础上，允许我修改自己的代码、打包新版本、重启应用，并在重启后继续目标或排队步骤。重启期间任务暂停，重启后由主进程自动接续。

## 审批层级

| 模式 | SDK 映射 | 应用层能力 |
| --- | --- | --- |
| 手动审批 | default | 每个敏感操作先问 |
| 允许所有编辑 | acceptEdits | 文件修改放行 |
| 完全访问 | bypassPermissions | 所有工具直接执行 |
| 自我进化 | bypassPermissions | 完全访问 + 重启 / 跨重启续跑 |

SDK 没有自我进化这一档，所以传给 CLI 的始终是 `bypassPermissions`；`selfEvolve` 只存在于应用层，并在 SDK 回报状态时保持不被降级。

## 工具

运行时在 `mcpServers.evolve` 注册三个工具，只有当前对话处于 `selfEvolve` 时可用：

- `schedule({ goal?, prompt?, command?, note? })`：保存重启后要继续的目标、指令或命令。
- `status()`：读取任务状态、步骤和结果。
- `restart({ version? })`：保存任务并安排重启；建议先运行 `npm run pack:release`，再传新版本号切换到新包。

## 跨重启流程

1. 工具把任务写到 `data/evolve/task.json`，包括对话 id、目标条件、待执行步骤和重启次数。
2. `restart` 调用主进程的 `restartWhenIdle`：等待所有对话空闲，然后 `app.relaunch()`（可指定新版本 exe）。
3. 新实例启动 2 秒后，`resumeEvolveTask()` 读取任务：
   - 切回原对话，恢复 `selfEvolve` 审批模式；
   - 依次执行待办的 `command` 步骤（PowerShell，10 分钟超时，输出截断 8 KB）；
   - 有目标条件时重新发送 `/goal <condition>`；
   - 发送待办的 `prompt`，并附上命令结果。
4. 失败的命令会把任务标为 `failed`，不再继续；重启次数上限 10 次。

命令是在**重启之后**执行的，不是应用关闭期间。这样不需要额外守护进程，也不会在应用不在时运行任何东西。

## 与目标模式联动

`schedule` 可以带 `goal`；任务文件保存目标条件，重启后重新发送 `/goal` 恢复 CLI 的目标循环。目标条在 `selfEvolve` 下显示「自我进化 · 重启后续跑」。目标轮数/时间上限仍使用设置里的目标预算。

## 安全边界

- 从其他模式切到自我进化时，确认弹窗用最高权限措辞说明自修改、重启和失败风险；用户必须手动输入「我授权你自动进化」，短语完全匹配前确认按钮保持禁用。
- 只有 `selfEvolve` 审批模式可用；切回其他模式立即停用工具。
- 工具只写任务文件，不直接执行命令；重启后的命令由主进程在应用工作目录执行。
- 单任务最多 50 步、10 次重启；命令超时 10 分钟；审计写入 `data/evolve/audit.log`。
- 重启前必须至少有一个待续步骤或目标，否则拒绝重启。
- 侧聊不注册自我进化工具，避免任务绑定到不会持久化的临时会话。

## 自我更新示例

1. 修改源码。
2. 运行 `npm run check`、`npm test`。
3. 更新 `package.json` 版本并运行 `npm run pack:release`。
4. `schedule({ prompt: '验证新版本并继续', command: 'npm run verify:asar' })`。
5. `restart({ version: '0.0.88' })`。
6. 新版本启动，执行命令、恢复目标并继续对话。
