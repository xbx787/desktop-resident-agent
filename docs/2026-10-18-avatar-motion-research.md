# 形象与动效调研记录（2026-10-18）

## GitHub 项目调研与采用边界

| 项目 | 可借鉴点 | 本项目采用方式 |
| --- | --- | --- |
| [Shimeji-ee 行为配置](https://github.com/DalekCraft2/Shimeji-Desktop/blob/main/conf/behaviors.xml) | 行为条件、权重和动作帧分离，避免把随机动作散落在界面代码里。 | 用单一状态解析器决定工作、等待、语音、完成、失败和待机的优先级；随机表情只在真正待机时运行。 |
| [pixi-live2d-display 动作指南](https://github.com/guansss/pixi-live2d-display/wiki/Complete-Guide#motion) | 动作优先级、表情管理和资源预热。 | 借鉴 idle / normal / force 的抢占思路及预加载；当前 PNG 素材不引入 Cubism 运行时。 |
| [OpenPet](https://github.com/dengyie/OpenPet) | 单一宠物状态服务管理动作与资源包。 | 状态由 `resolveAvatarPresentation` 统一归并，渲染层不再各自猜测任务状态。 |
| [Innate Labs desktop-pet](https://github.com/Innate-Labs/desktop-pet) | 用真实 Claude Code 运行事件驱动 run / wait / done，而不是假进度动画。 | 直接消费小鲸已有的 `taskStatus` 与 `avatarState`，状态点、表情和动作都跟随真实事件。 |
| [react-shimeji](https://github.com/CarbonNeuron/react-shimeji) | 有权重的待机行为、定时器清理和精灵资源生命周期。 | 待机动作稀疏触发，状态变化时取消旧计时器和旧动画回调。 |
| [L2dvpet](https://github.com/P1r2y/L2dvpet) | 注视、情绪和口型是未来 Live2D 路线的能力边界。 | 本轮保留轻量 PNG 方案；若未来升级 Live2D，应使用重新绑定的自有模型素材。 |
| [VPet](https://github.com/LorisYounger/VPet/blob/main/README_en.md#animation-copyright-notice-and-authorization-terms) | 代码授权与角色动画素材授权需要分别处理。 | 只借鉴状态和工程结构，不复制项目角色素材。 |

结论：当前最合适的是“固定窗口几何 + 视觉层动画 + 真实状态驱动”。Live2D 能提供注视和口型，但需要独立绑定模型；在现有 PNG 资源上强行接入只会增加运行时和素材漂移。

### 自动门禁的边界

`scripts/audit-active-avatar-assets.cjs` 只读取渲染代码实际引用的 PNG，检查缺图、格式与校验值、alpha 内容、立绘尺寸、独立头像画布、姿势图底边差异。有引用呆毛层时还会检查身体与呆毛画布一致性、旋转轴画布假设和 body 是否仍与完整原图相同；不使用呆毛层时不强制生成该层。旧 `scripts/sprite-audit.cjs` 仍负责生成暂存区诊断。`node scripts/audit-active-avatar-assets.cjs` 已接到正式打包前，这是质量闸，不应为发版而调低阈值。失败状态另有专用的歉意表情，不再错误复用“害羞”；sleepy / shy 的白色贴纸外框已去掉。

透明率、尺寸、锚点都不能证明画的是正确人物，也不能判断色彩、构图或表情是否可爱。身份与美术审查必须保留人工对照。所有新角色素材统一采用：透明背景、可辨识剪影、同一画笔线宽与阴影档位、统一 Q 版头身比；头像从与桌面立绘同一设计稿导出。运行中动效优先使用同一角色的表情和少量骨骼/分层变化，避免不同绘制来源整张跳换。
